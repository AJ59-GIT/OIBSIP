# Task 5 · Autocomplete and Autocorrect Analytics

Implements and compares frequency-based n-gram **autocomplete** and edit-distance **autocorrect** on a Project Gutenberg text, and measures both accuracy and efficiency.

## Files

| File | Purpose |
|---|---|
| `autocomplete_autocorrect.ipynb` | The full analysis: preprocessing, frequency analysis, autocomplete, autocorrect, metrics, comparison, discussion |
| `req_nlp.txt` | Python dependencies |
| `REPORT_autocomplete_autocorrect.md` | Written report of method and results |

Place `The_Project_Gutenberg.csv` next to the notebook (or in a `data/` folder). The notebook is saved without outputs; run it to generate all tables and charts.

**About the dataset:** despite the `.csv` extension the file is the plain text of *Alice's Adventures in Wonderland* (about 26,600 words), not a table, so it is read as text. The Gutenberg licence header/footer and table of contents are stripped automatically.

## Quick start

```bash
pip install -r req_nlp.txt
jupyter notebook autocomplete_autocorrect.ipynb     # then: Kernel -> Restart & Run All
```

Runtime is about one minute. NLTK stop-words are downloaded automatically when internet is available; otherwise a built-in copy of the same list is used.

## Configuration (first code cell)

| Setting | Default | Meaning |
|---|---|---|
| `CORPUS_PATHS` | `["The_Project_Gutenberg.csv"]` | Plain-text files to use; add more books to enlarge the corpus |
| `RANDOM_STATE` | `42` | Seed |
| `TEST_FRACTION` | `0.20` | Share of sentences held out for autocomplete evaluation |
| `TOP_K` | `3` | Suggestions shown per query |
| `MAX_EDIT_DISTANCE` | `2` | Autocorrect gives up beyond this many edits |
| `N_TYPOS_PER_KIND` | `250` | Synthetic misspellings per error type (4 types) |
| `N_CORRECT_WORDS` | `1000` | Correct words added to the autocorrect test to measure false corrections |

## What the notebook does

1. Loads the corpus into a pandas DataFrame (one row per paragraph).
2. Preprocessing: normalisation, sentence splitting, lower-casing, tokenisation, punctuation removal, NLTK stop-word removal.
3. Top 20 most frequent words (with and without stop-words), as bar charts.
4. **Autocomplete:** unigram, bigram and trigram-with-back-off models; a demo of 12 prefixes with top-3 predictions plus partial-word completion; evaluation on held-out text (Hit@1, Hit@3, Precision@3, Recall@3, coverage, speed, memory).
5. **Autocorrect:** Levenshtein, Damerau-Levenshtein and Norvig-style correctors (plus `pyspellchecker` if installed); a hand-written test of about 40 misspellings and a synthetic test of 1,000 misspellings plus 1,000 correct words; precision, recall, F1, accuracy.
6. Before/after confusion matrices for every approach, recall by error type, and an out-of-dictionary demonstration.
7. Comparison of accuracy and efficiency, and a discussion of limitations versus production keyboards.

## Headline results (seed 42)

| Autocomplete model | Hit@1 | Hit@3 | Hit@3 with 2 letters typed |
|---|---|---|---|
| Unigram | 6.0% | 12.2% | 66.5% |
| Bigram | 14.6% | 25.8% | 75.4% |
| Trigram + back-off | 16.0% | 28.0% | 75.7% |

| Autocorrect approach | Precision | Recall | F1 | Time per word |
|---|---|---|---|---|
| Levenshtein | 0.739 | 0.771 | 0.755 | about 13 ms |
| Damerau-Levenshtein | 0.826 | 0.862 | 0.844 | about 14 ms |
| Norvig-style | 0.828 | 0.864 | 0.846 | about 2 ms |

## Notes and limitations

- The corpus is small (2,610 distinct words), so results are limited by data more than by algorithm choice.
- NLTK and `pyspellchecker` were not installed in the environment where the notebook was tested. The stop-word fallback list was used, and the optional `pyspellchecker` comparison (a fourth corrector) is skipped automatically if the library is missing; that path is untested.
- Autocorrect only handles non-word errors, uses a closed dictionary, and ignores context.
- The misspellings in the large test are synthetic (generated by the notebook), not collected from real typing.
